# HE1T VCR

A self-contained, single-file video player page. Videos are stored in a `videos/` folder next to the page and are played by passing the video's filename as the `?v=` URL parameter. The page lists available tapes itself (via a small floating "Insert Tape" chooser) by reading the folder server-side — no directory indexing required.

## Requirements

- A PHP-capable web server (LiteSpeed, Apache, nginx + PHP-FPM, etc.) — the page is `index.php`
- PHP 7+ core functions only (`glob`, `json_encode`) — no extensions

## Usage

```
https://<your-host>/?v=wardogs_base.mp4
```

- `/?v=<filename>` plays the video named `<filename>` from `videos/`
- `/` (no parameter) shows the HE1T VCR splash screen (title + `vcr.png`)
- The floating `vhs.png` button (top-left) opens the "Insert Tape to Play" chooser, which lists every `.mp4` in `videos/` (descending by filename); clicking a tape navigates to `/?v=<filename>`
- If the video can't be loaded, a "Video not found" message is shown
- A download arrow appears below the video, allowing viewers to save the file

## Security

- Video URLs are restricted to the same folder. If the `?v=` parameter contains `..`, starts with `/`, or includes `://`, playback is rejected with an error. This prevents the page from being used to stream or proxy external content.
- `videos/` directory indexing is disabled (`videos/.htaccess` → `Options -Indexes`), so the folder cannot be browsed publicly; the tape list is only ever generated by the page itself.

## Discord Link Embeds

When a `/?v=<file>` URL is pasted into Discord, Discord's link preview fetcher reads the Open Graph tags the page emits and renders a **native playable video player** that streams the file directly from the server — instead of a plain link card. The page only emits these tags when `?v=` resolves to an existing file in `videos/`.

- Works on any domain (no whitelist) because it's a direct-file video embed, not an iframe embed.
- `og:video:width/height` are filled in from the tape's actual dimensions (read from the mp4 header's `moov`/`tkhd` boxes — core PHP only, no extensions) so the embed frame matches the video's aspect ratio; if they can't be determined, the tags are omitted and the player falls back to a default frame.
- The URL must be publicly reachable over HTTPS, and the file must exist when the link is posted — Discord fetches the page at message-send time.
- Posting the direct video URL (`https://<your-host>/videos/<file>.mp4`) also produces a native player without going through the page.
- Discord applies an unofficial size cap to link-embedded videos (order of tens-to-hundreds of MB, varies over time); very large files may fall back to a plain link card.
- If you change a file, post the link again — Discord caches link previews.

## Files

| File            | Purpose                                                       |
| --------------- | ------------------------------------------------------------- |
| `index.php`     | The player page (all logic, styles, and the PHP tape list)    |
| `vcr.png`       | Background image shown behind the video / on the splash       |
| `vhs.png`       | Floating "Insert Tape" button + row icon in the chooser       |
| `og-vcr.png`    | 1200×630 Open Graph image (link preview cards)                |
| `videos/`       | Video files (`*.mp4`); `.htaccess` disables directory listing |

## Deployment

Both layouts are supported — the page derives its absolute URLs (Open Graph video tags, thumbnail) from the request, so it behaves identically in either:

**Subdomain** — `https://vcr.example.com/`

1. Copy `index.php`, `vcr.png`, `vhs.png`, and `og-vcr.png` into a dedicated web root (e.g. `/home/<user>/vcr/`).
2. Place video files (`*.mp4`) in a `videos/` folder next to `index.php`.
3. Ensure the server runs PHP for `.php` files (standard on LiteSpeed/Apache; nginx needs a PHP-FPM upstream).
4. Point the domain/subdomain at that folder.

**Subfolder** — `https://example.com/vcr/`

1. Copy the same files into a subfolder of an existing web root (e.g. `webroot/vcr/`).
2. Place video files (`*.mp4`) in `webroot/vcr/videos/`.
3. Nothing else to configure — just make sure the subfolder is reachable over HTTPS.

Either way, share links in directory form (with the trailing slash, e.g. `https://example.com/vcr/?v=tape.mp4`) so the page's relative asset references resolve correctly.

No build step, no external dependencies — just static files plus PHP.
